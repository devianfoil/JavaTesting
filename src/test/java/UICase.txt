Deposit
1. Успешный депозит

Цель UI: пользователь может внести деньги через форму и видит успешный результат.
Precondition: пользователь залогинен, у него есть хотя бы один аккаунт.
Steps:
Открыть страницу Deposit Money.
Выбрать аккаунт в dropdown.
Ввести валидную сумму, например 100.
Нажать Deposit.
UI проверки:
форма доступна и элементы отображаются корректно;
отображается success message;
нет текста ошибки/валидации.
Финальная проверка на бэке:
до действия получить баланс выбранного аккаунта;
после депозита повторно получить баланс;
проверить, что баланс увеличился на сумму депозита.
2. Неуспешный депозит с невалидной суммой

Цель UI: UI корректно показывает ошибку при невалидной сумме.
Precondition: пользователь залогинен, у него есть аккаунт.
Steps:
Открыть страницу Deposit Money.
Выбрать аккаунт.
Ввести невалидную сумму: 0, отрицательную или больше лимита.
Нажать Deposit.
UI проверки:
отображается ошибка/валидация;
success message не отображается;
форма остается доступной для исправления.
Финальная проверка на бэке:
сохранить баланс до действия;
получить баланс после попытки депозита;
проверить, что баланс не изменился.
3. Неуспешный депозит с пустой формой

Цель UI: обязательные поля корректно валидируются на интерфейсе.
Precondition: пользователь залогинен.
Steps:
Открыть страницу Deposit Money.
Не выбирать аккаунт.
Не вводить сумму.
Нажать Deposit или проверить disabled state кнопки.
UI проверки:
отображается required validation или кнопка недоступна;
success message не отображается.
Финальная проверка на бэке:
получить список аккаунтов до действия и после;
проверить, что ни один баланс не изменился.
Transfer
4. Успешный перевод

Цель UI: пользователь может отправить перевод и видит успешное завершение операции.
Precondition: пользователь залогинен, у него есть аккаунт с достаточным балансом.
Steps:
Открыть страницу Make a Transfer.
Выбрать аккаунт отправителя.
Заполнить Recipient Name, Recipient Account Number, Amount.
Отметить Confirm details are correct.
Нажать Send Transfer.
UI проверки:
форма отправляется без ошибок;
отображается success message;
нет валидационных сообщений.
Финальная проверка на бэке:
сохранить баланс отправителя и получателя до перевода;
после перевода повторно получить оба баланса;
проверить списание у отправителя и зачисление получателю.
5. Неуспешный перевод с невалидной суммой

Цель UI: UI корректно сообщает об ошибке перевода при неверной сумме.
Precondition: пользователь залогинен.
Steps:
Открыть страницу Make a Transfer.
Заполнить форму валидными данными, кроме суммы.
Ввести 0, отрицательное значение, сумму больше лимита или больше баланса.
Подтвердить checkbox.
Нажать Send Transfer.
UI проверки:
отображается ошибка;
success message не отображается;
форма не ломается и доступна для исправления.
Финальная проверка на бэке:
получить балансы отправителя и получателя до действия;
получить их после попытки перевода;
проверить, что оба баланса не изменились.
6. Неуспешный перевод с незаполненной формой

Цель UI: обязательные поля и checkbox валидируются на клиенте.
Precondition: пользователь залогинен.
Steps:
Открыть страницу Make a Transfer.
Не выбирать аккаунт.
Не заполнять поля.
Не отмечать checkbox.
Нажать Send Transfer или проверить disabled state.
UI проверки:
отображаются required validations;
success message не отображается;
перевод не отправляется.
Финальная проверка на бэке:
получить балансы аккаунтов пользователя до и после;
проверить, что данные не изменились.
Edit Profile
7. Успешная смена имени

Цель UI: пользователь может изменить имя и видит успешный результат.
Precondition: пользователь залогинен и открыт экран Edit Profile.
Steps:
Открыть Edit Profile.
Ввести новое валидное имя из двух слов латиницей, например Alice Brown.
Нажать Save Changes.
UI проверки:
отображается success message;
страница остается рабочей;
новое имя отображается в UI после обновления/повторного открытия профиля.
Финальная проверка на бэке:
получить имя пользователя до действия;
после сохранения повторно получить профиль;
проверить, что имя изменилось на новое значение.
8. Нельзя сохранить текущее имя повторно

Цель UI: клиентская валидация не дает сохранить старое имя.
Precondition: пользователь залогинен и открыт экран Edit Profile.
Steps:
Открыть Edit Profile.
Ввести текущее имя пользователя.
Нажать Save Changes.
UI проверки:
отображается предупреждение о том, что новое имя совпадает с текущим;
success message не отображается;
пользователь остается на той же форме.
Финальная проверка на бэке:
получить профиль до и после;
проверить, что имя не изменилось.
9. UI корректно показывает ошибку для невалидного имени

Цель UI: UI правильно обрабатывает backend validation error.
Precondition: пользователь залогинен и открыт экран Edit Profile.
Steps:
Открыть Edit Profile.
Ввести невалидное имя: одно слово, не латиница или другой неверный формат.
Нажать Save Changes.
UI проверки:
отображается понятная ошибка для пользователя;
success message не отображается;
форма доступна для исправления.
Финальная проверка на бэке:
получить имя пользователя до и после;
проверить, что имя не изменилось.
